# 和 AI 一起读文献：实现方式

目标：读的时候随口说、AI 帮记；有疑问当场问；读完 AI 把想法整理进画板。

## 结论

先做「方案 B + 方案 C」，暂不在画板里内嵌 AI 聊天窗口。

1. **让 AI 能直接读写画板文件（B）。** 画板已经是 JSON 文件，页面已经会自动载入外部修改。给 Claude 一套「读画板 / 加节点 / 连线」的 MCP 工具，现有的 Claude 对话窗口就是伴读窗口，没有额外 API 费用。
2. **画板里加一个「收件箱」（C）。** 阅读时只丢一句话速记（打字或语音），读完让 AI 一次性归类。
3. **AI 写进画板的内容一律标「待确认」。** 虚线边框，点确认才算数，避免分不清论文原话、自己的想法和 AI 的概括。

用顺手后如果想要一个窗口搞定，再做方案 A；B 和 C 做的东西届时都能复用。

## 方案 A：画板内嵌 PDF 和 AI 聊天（以后再做）

一个窗口三栏：论文、对话、画板。

- 优点：体验最完整，AI 知道当前页和选中的文字。
- 缺点：工作量最大（PDF 阅读器、聊天界面、本地服务调 AI）；需要 API key，按用量另外付费。

## 方案 B：Claude 直接读写画板文件（推荐，先做）

两个窗口：Claude 对话窗口负责听、答、记；MindBoard 负责显示。

- 做法：MCP 工具，动作为列出画板、读成大纲、在节点下加子节点或卡片、加连线。写入走 MindBoard 本地服务，冲突保护照常生效。
- 优点：工作量最小；用现有订阅；Claude 读 PDF、联网查相关工作的能力直接可用。
- 缺点：要切窗口；AI 不知道读到哪，需要说页码或贴原文；人和 AI 同时写入可能触发冲突副本，需要把 AI 写入做成「追加节点」而不是整份覆盖。

## 方案 C：阅读时只收集，读完再整理（推荐，和 B 一起做）

画板左侧一条「收件箱」，一个快捷键随时丢进去一句话。

- 理由：读论文时最贵的是注意力，分类交给读完之后的 AI。
- 语音：Windows 自带听写（`Win`+`H`）今天就能用；或页面内「按住说话」，用 Chrome 内置识别（音频会发到 Google，需联网）。
- 缺点：中英文夹杂的术语识别容易错，整理时由 AI 对照原文纠正。

## 一次阅读的流程

读前（AI 出骨架卡：主张 / 方法 / 发现 / 局限）→ 读中（速记进收件箱，疑问当场问）→ 读后说「整理」（AI 归类、补页码、标待确认）→ 你确认 → 攒够几篇后横向对比、画连线。

## 相对工作量（经验估计，不是测量值）

| 方案 | 相对开发量 | 额外费用 | AI 是否知道读到哪 |
| --- | --- | --- | --- |
| C 收件箱 + 语音 | 1 | 无 | 靠你说 |
| B AI 读写画板 | 1.5 | 无 | 靠你说 |
| A 内嵌 PDF + 聊天 | 6 | API 按量计费 | 知道 |

## 让阅读更高效的做法

- 笔记分三种样子：原文摘录、我的想法、AI 整理（待确认）。
- 每条笔记带出处：哪篇、第几页，AI 记的也一样。
- 分三遍读：5–10 分钟略读决定去留；第二遍抓论证；第三遍只留给真正要用的。
- 让 AI 反过来提问，答不上来的地方就是没读懂的地方。
- 每读 3–5 篇做一次横向对比（方法 / 数据 / 结论 / 局限）。
- 核心论文可以先用已有的「精读」技能拆成小卡片，再进 MindBoard 串成图。
